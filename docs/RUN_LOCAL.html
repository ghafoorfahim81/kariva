راهنمای اجرای کاریوا (Kariva) روی کامپیوتر

دو روش: با Laravel Herd (آدرس backend.test) یا با php artisan serve (آدرس localhost:8000)

۱. نیازمندی‌ها

ابزارتوضیح
PHP 8.3 یا بالاتربا extensionهای pdo_pgsql، pgsql، intl (و redis فقط اگر Redis استفاده می‌کنید). در Herd همه از قبل هست، جز pdo_pgsql که شاید لازم باشد فعال شود.
Composerبرای نصب بستهٔ PHP
Node.js 20 یا بالاتربرای فرانت (Vite)
PostgreSQL 16 یا بالاتربا extension به نام pg_trgm (جزو extensionهای استاندارد است)
Redisبرای کار محلی لازم نیست. فقط روی سرور اصلی لازم است (بخش ۸ را ببینید).

۲. راه‌اندازی مشترک (برای هر دو روش)

الف) دیتابیس

در pgAdmin یا psql دو دیتابیس بسازید (کاربر و رمز دلخواه، فقط باید با .env یکی باشد):

CREATE ROLE kariva LOGIN SUPERUSER PASSWORD 'kariva';
CREATE DATABASE kariva OWNER kariva;
CREATE DATABASE kariva_test OWNER kariva;

اگر از کاربر postgres استفاده می‌کنید، در مرحلهٔ بعد همان را در .env بگذارید.

ب) بک‌اند

cd backend
composer install
copy .env.example .env        (در PowerShell: Copy-Item .env.example .env)
php artisan key:generate

سپس در backend/.env این مقدارها را برای کار محلی تنظیم کنید (بدون Redis):

DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=kariva
DB_USERNAME=kariva
DB_PASSWORD=kariva

SESSION_DRIVER=file
CACHE_STORE=file
QUEUE_CONNECTION=sync

OTP_DRIVER=screen

با OTP_DRIVER=screen کد ورود مستقیماً روی فرم ورود نشان داده می‌شود — نیازی به SMS یا WhatsApp نیست.

php artisan config:clear
php artisan migrate --seed
php artisan storage:link

دستور اول ۳۰ جدول و دادهٔ اولیه (۳۴ ولایت، شهرها و دسته‌بندی‌ها) را می‌سازد. دستور storage:link یک لینک سمبلیک می‌سازد که آپلود فایل‌ها روی مرورگر نمایان شود؛ بدون آن عکس‌های پروفایل باز نمی‌شوند.

فایل .env رمز و تنظیمات شخصی شما را دارد و در git نمی‌رود. در گیت فقط .env.example هست.

۳. روش اول: با Laravel Herd

  1. Herd را باز کنید و در بخش Sites با Add پوشهٔ E:\kariva\backend را اضافه کنید (پوشهٔ بک‌اند، نه پوشهٔ اصلی پروژه).
  2. سایت backend.test ساخته می‌شود. نسخهٔ PHP را 8.3 یا 8.4 بگذارید.
  3. در PHP > php.ini (در Herd) خط‌های extension=pdo_pgsql و extension=pgsql را از حالت کامنت دربیاورید و Herd را دوباره راه بیندازید.
  4. بررسی کنید: آدرس http://backend.test/api/v1/health باید {"status":"ok"} بدهد.
  5. فرانت را در ترمینال جدا اجرا کنید و پروکسی را به Herd بدهید:
cd kariva-v4.8
npm install
$env:KARIVA_API="http://backend.test"; npm run dev

سپس http://localhost:5173 را باز کنید. دستور بالا مخصوص PowerShell است؛ در CMD از set KARIVA_API=http://backend.test و بعد npm run dev استفاده کنید.

در Herd رایگان نیازی به php artisan serve نیست. Herd خودش سرور را روشن نگه می‌دارد.

۴. روش دوم: با php artisan serve

این روش بدون Herd هم کار می‌کند. دو ترمینال باز کنید.

ترمینال ۱: بک‌اند

cd backend
php artisan serve

API روی http://127.0.0.1:8000/api/v1 بالا می‌آید.

ترمینال ۲: فرانت

cd kariva-v4.8
npm install
npm run dev

چون پیش‌فرض پروکسی Vite همان http://127.0.0.1:8000 است، متغیر KARIVA_API لازم نیست. فرانت روی http://localhost:5173 باز می‌شود.

۵. مقایسهٔ دو روش

Herdphp artisan serve

در هر دو روش مقدار SANCTUM_STATEFUL_DOMAINS=localhost:5173,127.0.0.1:5173 در .env می‌ماند، چون مرورگر همیشه از آدرس 5173 با API حرف می‌زند و پروکسی Vite درخواست‌ها را می‌فرستد.

۶. کارهای بعد از اجرا

  • ساختن ادمین: php artisan kariva:make-admin +93700000000 (شمارهٔ ثبت‌شده در سایت را بگذارید).
  • اجرای تست‌ها: php artisan test (به دیتابیس kariva_test نیاز دارد).
  • بررسی آمادگی برای سرور: php artisan kariva:preflight.
نحوهٔ ورود در حالت محلی: شماره‌تلفن را بزنید، کد ۶ رقمی روی همان فرم نمایان می‌شود؛ همان را وارد کنید. با هر شمارهٔ ایرانی (شروع با ۰۷) می‌توانید وارد شوید. کد‌ها در لاگ هم ثبت می‌شوند: storage/logs/laravel.log

۷. خطاهای رایج

خطاعلت و راه‌حل
RedisException: No connection could be made...Redis روشن نیست. در .env: SESSION_DRIVER=file، CACHE_STORE=file، QUEUE_CONNECTION=sync و بعد php artisan config:clear.
Driver [fileq] not supported (یا مشابه)غلط املایی در .env. مقدار درست file است.
could not find driverextension pdo_pgsql در PHP فعال نیست (بخش ۳، مرحلهٔ ۳).
connection refused روی پورت 5432سرویس PostgreSQL روشن نیست، یا پورت/رمز در .env اشتباه است.
تغییر .env اثر نکردphp artisan config:clear را بزنید.
فرانت بالا می‌آید ولی داده نمی‌گیرد (502 یا 500 در /api)بک‌اند در دسترس نیست. آدرس /api/v1/health را مستقیم باز کنید و KARIVA_API را با روش خود مطابقت بدهید.
صفحهٔ اصلی backend.test خطا یا 404 می‌دهدطبیعی است؛ بک‌اند فقط API است. از /api/v1/health استفاده کنید.
کد ورود نشان داده نمی‌شودمطمئن شوید OTP_DRIVER=screen در .env باشد و بعد php artisan config:clear بزنید. اگر کد نشان نداد، لاگ را ببینید: storage/logs/laravel.log
خطا: «چند بار درخواست کد کرده‌اید»به ازای هر شماره، در ساعت تعداد محدودی OTP مجاز است. یک ساعت صبر کنید یا یک شمارهٔ دیگر امتحان کنید.
Duplicate key value violates unique constraintMigration قبلاً اجرا شده. اگر می‌خواهید دوباره از صفر شروع کنید: php artisan migrate:fresh --seed (همهٔ داده‌ها حذف می‌شود).
عکس‌ها بالا می‌آیند ولی نمایش داده نمی‌شوندphp artisan storage:link را اجرا نکرده‌اید. یک بار آن را بزنید.

۸. Redis (فقط برای سرور اصلی)

در سرور اصلی Ubuntu، .env باید SESSION_DRIVER=redis، CACHE_STORE=redis، QUEUE_CONNECTION=redis داشته باشد و Redis روشن باشد. جزئیات در docs/DEPLOY.md است.
